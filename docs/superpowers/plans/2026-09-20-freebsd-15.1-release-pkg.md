# FreeBSD 15.1 官方發行支援實作計畫

> **執行技能：**逐項實作時必須使用 `mur-executing-plans`；每個 Task 各自測試、審查、提交，不得把未通過的步驟併入下一項。

**Goal:** 為 FreeBSD 15.1 amd64 提供原生驗證的五二進位 tarball、通過依賴閘門的 `.pkg`、安全的 draft-release 協調，以及正確的 pkg 更新行為。

**Architecture:** `release/binaries.toml` 是所有平台封裝清單的唯一來源，跨平台 Python helper 提供 CI 與測試穩定介面。GitHub Actions 建立 draft 並保有最終發布權；Cirrus 在 FreeBSD 15.1 原生建置、測試與上傳，finalizer 以固定的 check identity、資產集合及 checksum 閘門決定是否發布。FreeBSD package 路徑必須先由無祕密 spike 實測選定；結果未通過前，`.pkg` 與官方支援啟用均 fail closed。

**Tech stack:** Rust 2024、Python 3.11+ 標準函式庫、POSIX sh、GitHub Actions、Cirrus CI FreeBSD、FreeBSD ports/pkg/poudriere、GitHub CLI/API。

## Global Constraints

- FreeBSD 官方支援範圍僅為 FreeBSD 15.1 amd64 CLI；Hub/GUI、arm64、舊版 FreeBSD、rc.d 自動服務安裝不在範圍內。
- 發行物固定包含 `mur`、`mur-mcp-server`、`murmurd`、`mur-agent-runtime`、`mur-research-gateway`，唯一清單來源是 `release/binaries.toml`。
- 平台專屬功能無 FreeBSD 實作時必須明確回報 unsupported，不得落入 Linux 路徑、systemd、Linux sandbox 或 Linux 桌面整合。
- GitHub Actions 是唯一可把 draft release 轉為 published 的主體；Cirrus 只能上傳兩個 FreeBSD 資產。
- FreeBSD check、資產、checksum、package 依賴或上游工作任一失敗時，release 必須保留 draft，Homebrew 與 crates.io 必須跳過。
- Cirrus token 僅可供 canonical repository 的版本 tag release task 使用，不得進入 PR、fork、cache、artifact、poudriere 或程序參數日誌。
- 若 `ldd` 顯示未由 FreeBSD base 提供的動態依賴，且未提供簽章 pkg repository，release-attached `.pkg` 必須停止發布；不得把依賴轉嫁成手動安裝清單。
- `pkg install mur` 只能在 FreeBSD Ports/package repository 正式供應後宣稱；GitHub Release URL 使用 `pkg add`。
- 所有路徑處理須跨 macOS、Linux、Windows；Rust 使用 `Path`/`PathBuf`，Python 使用 `pathlib.Path`，不得新增硬編碼路徑分隔假設。
- 不得覆寫或提交工作樹中既有、與本計畫無關的修改。

## 自我審查

- **Spec coverage:** manifest §3→Task 1；平台審計/行為 §7–8→Tasks 2–3；poudriere feasibility/timing/check identity §3.1–3.2/§5.1→Tasks 4–5；native tarball §3→Task 6；pkg/依賴 §4→Task 7；draft/finalizer/checksum §2/§5→Task 8；cleanup/docs §5.3/§9→Task 9；成功與失敗 rehearsal→Task 10。
- **Cross-task consistency:** check 名稱與 app slug 只來自 `release/freebsd-policy.toml`；binary names 只來自 `release/binaries.toml`；workspace version 是 tag、port 與 package filename 的唯一版本來源。
- **Fail-closed points:** Task 4 feasibility、Task 7 runtime dependency、Task 8 checks/assets/upstream jobs、Task 10 failure rehearsal；任一未通過都不可宣稱官方支援。
- **完整性掃描：**本計畫不允許待定內容、猜測 app slug、猜測 dependency 或未量測 package mode；實測值由 Task 4/5 產生並在後續 Task 消費。
