# LanceDB 0.26 → 0.39 upgrade — design

**Status:** landed on `lancedb =0.37.1` (originally targeted 0.39.0)

## Status

Target version: 0.37.1 (originally 0.39.0).
Reason: lancedb 0.38.0 / 0.39.0 do not compile without the `remote` feature —
`src/job.rs` uses `Error::Http`, which `src/error.rs` gates behind
`#[cfg(feature = "remote")]` (lancedb/lancedb#4142; fixes #4233 / #4103 unmerged).
Enabling `remote` was rejected: it adds tonic / arrow-flight / prost, a second
reqwest 0.11 / hyper 0.14 / h2 0.3 stack, and a second `object_store` (0.13 + 0.14)
only to compile a gRPC client MUR never uses. The move to 0.39.0 is a follow-up PR
once the upstream fix is released. With 0.37.1 the resolved set is lance 10.0.0,
arrow 58.4.0, datafusion 54.1.0, tantivy 0.24.2 — no duplicate heavy crates.
The version table below records the original 0.39 plan.
**Scope:** routine maintenance (option A): bump versions, compile, prove existing
on-disk tables open or rebuild, keep query behavior unchanged. No new LanceDB
features are adopted.

## 4. Failure handling for unreadable tables

### Where it fails
`lancedb::connect` is lazy (`lancedb.rs:53-59`); format incompatibility surfaces
at `open_table` or at the first query, not at `open`. Wrapping only `open` would
catch nothing.

### What the error type can and cannot tell us
Checked against `lancedb-0.39.0/src/error.rs` (cached registry source):

- There is **no version/format-incompatibility variant.** Open failures arrive as
  `TableNotFound` (`table.rs:2752`, from `lance::Error::DatasetNotFound`) or fall
  through `impl From<lance::Error>` (`error.rs:182-199`) into the catch-all
  `Error::Lance { source: lance::Error }`.
- `Error::TableCorrupted` ("exists but could not be loaded (it may be corrupt or
  incomplete)") is declared at `error.rs:65` but is **not constructed anywhere**
  in the crate's `src/`, so it cannot be relied on.
- `lance-core` 12 source is not in the local registry yet; its variants are
  re-checked in commit 1 after `cargo fetch`.

Conclusion: "incompatible" cannot be detected from the type. Classification is
by **stage plus exclusion**, not by error kind.

### Classification rule
An `open_table` or first-query failure on a table directory that exists is
classified `Unreadable`, **except**:

| Error | Classified as | Why |
|---|---|---|
| `TableNotFound` | existing create/empty path | not a stale table |
| I/O permission denied / not-a-directory (walk the `source()` chain for `std::io::ErrorKind::PermissionDenied`) | `Io` — no rebuild hint | rebuilding would not help and could mislead |
| `NotSupported` (unsupported filesystem, `error.rs:184-188`) | `Io` — no rebuild hint | same |
| anything else | `Unreadable` | rebuild hint + original error chained |

False positives are acceptable by construction: every table in §3 is derived
data, so a wrong rebuild hint costs a rebuild, never data loss. The variant is
named `Unreadable`, not `Incompatible`, because the code cannot prove the cause.

### Routing rule
The generic store must not infer the rebuild command from a filesystem path —
that hardcodes the `~/.mur` layout into a reusable type. Instead:

- `LanceStore` returns `VectorStoreError::Unreadable { table, cause }`, where
  `table` is the Lance table name (`"patterns"`, `"sources"`, …) and `cause` is
  the underlying `lancedb::Error`, marked `#[source]`. The field is deliberately
  not called `source`: in this codebase "source" already means a source
  connector and the skill `source_id`.
- Each **caller** (the owner in the table above) maps that error to its own
  rebuild command in the user-facing message. The caller already knows which
  table it opened, so the two `sources` tables cannot be confused.
- Never panic; never surface a raw Arrow/Lance error without the rebuild hint
  (for `Unreadable`) or without the path (for `Io`).

### Message shape
```
The <what> index was written by an older LanceDB version and cannot be read.
Rebuild it with: <command>
```

## 5. Acceptance

1. `cargo clippy --all --all-targets --no-deps --locked -- -D warnings` and
   `cargo fmt --all -- --check` pass.
2. `cargo test -p mur-core` passes.
3. `cargo tree -d` shows a single version each of `arrow-*`, `lance*`,
   `datafusion*`, `tantivy`.
4. For each table in §3, using a copy of a real 0.26-written table:
   either it opens and queries return the same top-k as before the upgrade, or
   it fails with the §4 message and the listed rebuild command restores it.
5. **Opens but returns wrong data.** 0.26 → 0.39 spans 13 minors; the silent
   failure is a table that opens and queries without error but yields a changed
   schema or reinterpreted values. For every table that opens in item 4:
   - Before the bump, with the 0.26 build, dump from the table copy: the Arrow
     schema (field names, types, nullability, vector dimension) and a fixed
     sample of rows (first 5 by primary key, ordered explicitly). Store it as a
     run artifact, not in the repo.
   - After the bump, dump the same copy the same way and diff. Schema must be
     identical; sampled rows must match field-for-field, with vector floats
     compared bit-exact.
   - Per-table spot checks on top of the diff:

     | Table | Check |
     |---|---|
     | `index/patterns.lance` | vector dimension equals the configured embedding dimension |
     | `index/sources.lance` | sampled `source_id` values are connector ids, never `"skill"` |
     | `lance/sources.lance` | sampled `source_id` values are all `"skill"` |
     | `indexes/codebase/<project>.lance/chunks.lance` | for a sampled row, `content` equals lines `line_start..=line_end` of `file` at the indexed commit |

   This is sampling, not a full comparison. Its job is to catch a systematic
   reinterpretation, which shows up in any row.

   Dumps and diffs are produced by the `#[ignore]` tool in
   `mur-core/tests/lance_export.rs`, run unchanged against both builds so the
   dump logic is not a variable. Before comparing across versions, each
   table is dumped twice on the same build and must diff clean.

   A live `index/sources.lance` may be empty, which makes its `source_id`
   check vacuous. In that case a populated fixture is produced with the 0.26
   build in an isolated `HOME`/`MUR_HOME`: a three-note Obsidian vault added
   via `mur source add obsidian` and indexed via `mur source sync`, then
   frozen with a checksum list. Its rows must carry the connector instance
   id (e.g. `obsidian:<instance>`) as `source_id`.
6. Regression tests at the `LanceStore` seam: a garbage `_versions` manifest
   yields `Unreadable`; a permission-denied table dir yields `Io` with no
   rebuild hint; neither panics.

Environment note: on macOS use `stat -f '%Sm %N'`, not GNU `stat -c`.
