一、關鍵錯誤與修正

原計劃中有三個會導致實作階段驗證失敗的錯誤，以及七個安全/架構缺陷。以下逐一說明。

🔴 錯誤 1：predicate JSON round-trip 風險

🔴 錯誤 2：JCS canonicalization 不存在於程式碼

🔴 錯誤 3：MCP 指令 deny-list 存在大量繞過向量

原 deny-list 只擋了

sh, bash, zsh,
python / python3
（無 subcommand 時）

完全沒擋的繞過向量

ruby -e 'system(...)'
perl -e 'exec(...)'
php -r 'shell_exec(...)'
node -e / deno eval / bun -e
lua -e / awk 'BEGIN{system(...)}'
pip install evil && evil-cmd
npx evil-pkg （任意 npm 套件）
.DLL （大小寫繞過）
.so.1 （版本化繞過）

修正後：六層防禦

🟡 其他安全/架構修正

金鑰輪替重放攻擊

原設計未驗證 rotation manifest 的 issued_at。攻擊者可重放歷史輪替 manifest 復活已 superseded 的金鑰。修正：新增 last_rotation_at 欄位，拒絕時間不嚴格遞增的輪替。

已知 author 能力悄然擴張

原設計：同一 author 的後續 agent 靜默安裝。攻擊者可先建立信任再發布惡意版本。修正：即使是已知 author，每次安裝仍顯示一行權限摘要，需點擊確認。

trust store 路徑與鎖定

Commander 現有 ~/.mur/trust.json（JSON，無 file lock）與 spec 定義的 ~/.mur/trust/trust.yaml 不一致。修正：定義遷移路徑，新增 flock/LockFileEx 實作要求。

sidecar 生命週期矛盾

現有 mur-gui-core/src/sidecar.rs（421行）是 Hub spawns children 模型。Spec §3.1 要求 launchd 管理。修正：標註現有程式碼為 v0 實作，M-export-5 遷移。
